# rest_hours · 休息时段

给 AstrBot 机器人定个作息：该休息的时候不吭声，休息结束后把攒下的消息自然地补回。

- 休息时段、高峰时段**全部可配置**，支持多个时段、跨夜
- 支持法定节假日、调休上班日
- 休息期间拦在 LLM 之前，不消耗 token
- 队列落盘，重启不丢
- 只依赖 AstrBot 公开 API，无第三方依赖

> 版本 1.1.6 ｜ 需要 AstrBot `>= 4.16, < 5`

---

## 一、它做什么

| 阶段 | 行为 |
|---|---|
| 休息时间收到消息 | **只入队、不回复**（在调用模型之前就拦下） |
| 同一个人连发多条 | 队列里逐条记录，补回时按会话合并成一次回复 |
| 休息结束 | 后台轮询（20 秒一次）发现已不在休息时段，按会话逐条补回 |
| 补回失败 / 模型报错 | 这批消息退回队列，下一轮重试，不丢消息 |
| 重启 AstrBot | 队列已落盘，重启后接着攒、接着补 |

默认规则：**23:00–07:00** 休息；工作日（周一至周五、排除法定节假日）的 **09:00–12:00、14:00–18:00** 也算休息。

---

## 二、拦截范围

只有「本来就会回复」的消息才会被拦：

- 私聊：全部消息
- 群聊：只有 **@机器人** 或触发唤醒词的消息

群里没人叫它的闲聊不入队 —— 那些本来也不回复。

**例外**：管理员在**私聊**里发消息不受休息时段限制，方便随时调试。

---

## 三、配置

安装后进入 `插件 → 休息时段 → 配置`。五个字段，改完**最多 20 秒自动生效，不用重启**。

| 字段 | 默认 | 说明 |
|---|---|---|
| `rest_slots` | `23:00-07:00` | 休息时段，每行一个，可多个 |
| `peak_slots` | `09:00-12:00`<br>`14:00-18:00` | 高峰时段，每行一个，可多个；**留空 = 不启用** |
| `peak_apply_days` | `workday` | `workday` 周一至周五且排除法定节假日；`weekday` 只看星期；`everyday` 每天；`never` 关闭 |
| `extra_holidays` | 空 | 额外当节假日处理的日子，每行 `YYYY-MM-DD` |
| `extra_workdays` | 空 | 调休上班日，每行 `YYYY-MM-DD`；这些日子即使周末也算高峰 |

### 时段写法

每行一个，以下写法都支持，可混用：

```
23:00-07:00      # 跨夜：起点大于终点
12:00-13:30
9-12             # 可省略分钟
09：00—12：00     # 全角冒号、破折号也认
```

- 空行和 `#` 开头的行会被忽略
- 跨夜统一用「起点 > 终点」，不要写 `23:00-25:00`
- 格式不对的行会跳过并在日志里点名，不会让整份配置失效
- `rest_slots` 全部无效 → 回退默认 `23:00-07:00` 并告警
- `peak_slots` 明确留空 → 不启用高峰；写了但全部无效 → 回退默认并告警

### 示例：午休一小时 + 深夜到早上

```
rest_slots = 23:00-07:00
             12:00-13:30
```

### 示例：只留午休，不要高峰时段

```
rest_slots      = 12:00-13:30
peak_slots      =
peak_apply_days = never
```

## 四、指令

| 指令 | 权限 | 作用 |
|---|---|---|
| `/rest`、`/休息状态` | 仅管理员 | 查看当前是否休息、生效时段、待补回条数 |

私聊直接发送；群聊需先唤醒（@机器人 或配置的唤醒前缀）。

```
🕐 现在 2026-10-24 22:24 · 工作中（正常回复）
休息时段：23:00-07:00
高峰时段：09:00-12:00、14:00-18:00（生效日：workday）
额外节假日 0 天 · 调休上班日 0 天
待补回消息：0 条
```

## 五、补回是什么样

补回不是复述原话。插件把这期间的消息按时间排序拼成一段提示交给模型，要求它：

- 像刚忙完回来一样自然地回应
- 同一个人发的多条合并成一段
- 不解释「消息被延迟」这类系统细节
- 「刚在休息 / 刚忙完」最多说一句

补回使用 AstrBot 当前默认提供商和默认人格，语气与人设与平时一致。

如果装了 `astrbot_plugin_persona_selfedit`，补回时还会把它的「成长层」（机器人自己写的名字、喜好、习惯、说话方式、羁绊、共同记忆）一起注入 system prompt，所以补回的语气和它平时聊天时一致，而不是退回出厂设定。私聊和群聊都生效。

这个注入有三道前提，任何一条不满足就只用基础人设，不会报错、也不会用过期数据：

| 情况 | 行为 |
|---|---|
| 没装 `persona_selfedit` | 不注入，日志 `[rest] 未安装 astrbot_plugin_persona_selfedit，本次不注入成长层` |
| 装了但被禁用 | 不注入，日志 `[rest] astrbot_plugin_persona_selfedit 已禁用，本次不注入成长层` |
| 已启用但状态文件缺失/损坏 | 不注入或退回内置简化格式，日志告警一行，补回照常进行 |

禁用插件后，下一次补回就生效，不需要重启 AstrBot。成长层数据文件不会被删除，重新启用后立即恢复注入。

## 六、数据与日志

- 队列文件：`data/plugin_data/astrbot_plugin_rest_hours/queue.json`（首次有消息入队时创建）
- 每次变更原子写盘（先写 `.tmp` 再替换），文件损坏时按空队列处理，不阻塞插件启动
- 日志前缀统一为 `[rest]`：

```
[rest] 生效配置：休息 23:00-07:00 ｜ 高峰 09:00-12:00、14:00-18:00（workday）｜ 额外节假日 0 天 ｜ 调休上班 0 天
[rest] 休息时段暂存 #1 qq:GroupMessage:123456789 某用户: 在吗
[rest] 休息结束补回 2 条 → qq:GroupMessage:123456789，发送成功
[rest] 检测到配置变化，已重新加载时段规则
```

## 七、已知限制

| 限制 | 说明 |
|---|---|
| 单条截断 500 字 | 超出部分不入队 |
| 每轮最多补回 50 条 | 剩余消息下一轮继续，避免一次刷爆 |
| 非文本消息 | 图片、表情等只记为 `[非文本消息]` 占位 |
| 补回消耗 token | 每轮补回一次模型请求；休息越久攒得越多 |
| 节假日表内置 | 内置 2026 年法定节假日（33 天）；跨年需更换代码中的表，临时假期用 `extra_holidays` 补 |
| 固定北京时间 | 固定 `Asia/Shanghai`，不随机器时区变化 |
| 群里补回不带 @ | 群内补回为直接发送；多人同时等待回复时可能像自言自语 |

## 八、安装

**插件市场**：搜索「休息时段」安装，配置里按需改时段即可。

**手动安装**：把整个目录放到 `<AstrBot>/data/plugins/astrbot_plugin_rest_hours/`，目录名必须与 `metadata.yaml` 的 `name` 一致，然后重启 AstrBot。

## 九、文件结构

```
astrbot_plugin_rest_hours/
├── main.py            # 插件主体：配置解析、时段判断、入队、补回
├── _conf_schema.json  # 面板配置项定义
```

```bash
docker compose exec astrbot python3 /AstrBot/data/plugins/astrbot_plugin_rest_hours/test_slots.py
# 结果：全部通过
```

## 十、故障排查

| 现象 | 排查 |
|---|---|
| 休息时间还在回复 | 看日志有无 `生效配置`；确认该消息是私聊或群里 @ 了机器人；确认不是管理员私聊 |
| 一直在休息 | 检查 `rest_slots` 是否写成了全天，或 `peak_apply_days=everyday` 且高峰时段覆盖了全天 |
| 改配置没反应 | 等 20 秒；仍无变化则重启 AstrBot |
| 休息结束没补回 | 日志搜 `补回`；确认提供商可用（无提供商时会记录 `没有可用提供商` 并重试） |
| 补回语气像出厂设定 | 日志搜 `成长层`；多半是 `persona_selfedit` 未安装或已禁用，或 `persona_state.json` 缺失 |
